🚨 Problemas Comuns do Backend

❌ Erro: "Port 8080 already in use"

Sintoma

***************************
APPLICATION FAILED TO START
***************************

Description:

Web server failed to start. Port 8080 was already in use.

Causas Possíveis

  • Backend já está rodando em outra janela
  • Outra aplicação (Tomcat, outro Spring Boot) usando porta 8080
  • Processo ficou travado após encerramento incorreto

Soluções

Solução 1: Usar script para parar 
.\parar-sistema.bat
Solução 2: Matar processo Java manualmente 
taskkill /F /IM java.exe
Solução 3: Identificar e matar processo específico 
# Ver qual processo usa a porta 8080
netstat -ano | findstr :8080

# Saída exemplo: TCP 0.0.0.0:8080 0.0.0.0:0 LISTENING 12345
# O número final (12345) é o PID

# Matar o processo específico
taskkill /F /PID 12345
Solução 4: Mudar a porta do backend

Edite application.properties:

server.port=8081

⚠️ Atenção: Se mudar a porta, atualize também no frontend (scripts.js)

❌ Erro de Compilação

Sintoma

[ERROR] Failed to execute goal org.apache.maven.plugins:maven-compiler-plugin
[ERROR] Compilation failure
[ERROR] ... cannot find symbol

Soluções

Solução 1: Limpar e recompilar 
cd backend
mvnw.cmd clean compile
Solução 2: Reimportar dependências 
mvnw.cmd clean install -U
Solução 3: Verificar versão do Java 
java -version
# Deve ser Java 21 ou superior

❌ Erro de Conexão MySQL

Sintoma

com.mysql.cj.jdbc.exceptions.CommunicationsException: 
Communications link failure

The last packet sent successfully to the server was 0 milliseconds ago.

Causas Possíveis

  • MySQL não está instalado
  • MySQL não está rodando
  • Credenciais incorretas em application-mysql.properties
  • Banco de dados não existe

Soluções

Solução Rápida: Usar H2

Edite application.properties:

spring.profiles.active=h2
Solução MySQL: Verificar serviço 
# Windows - Verificar se MySQL está rodando
sc query MySQL80

# Iniciar MySQL
net start MySQL80
Solução MySQL: Verificar credenciais

Edite application-mysql.properties:

spring.datasource.url=jdbc:mysql://localhost:3306/seja_senai_db
spring.datasource.username=root
spring.datasource.password=SUA_SENHA_AQUI
Solução MySQL: Criar banco 
mysql -u root -p
CREATE DATABASE seja_senai_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

🌐 Problemas Comuns do Frontend

❌ Erro: "Port 5500 already in use"

Sintoma

OSError: [WinError 10048] Apenas uma utilização de cada endereço de soquete 
(protocolo/endereço de rede/porta) é normalmente permitida

Soluções

Solução 1: Parar servidor
  • Pressione Ctrl+C na janela do servidor
  • Ou execute: .\parar-sistema.bat
Solução 2: Matar processo na porta 5500 
# Ver processo usando porta 5500
netstat -ano | findstr :5500

# Matar o processo
taskkill /F /PID [número_do_processo]
Solução 3: Usar porta diferente 
# Python
python -m http.server 8000

# Node.js
npx http-server -p 8000

❌ Erro: "Python não encontrado"

Sintoma

Python não foi encontrado; executar sem argumentos para instalar do 
Microsoft Store...

Soluções

Solução 1: Script tenta Node.js automaticamente

O script iniciar-frontend.bat detecta Node.js automaticamente se Python não estiver disponível.

Solução 2: Instalar Python
  1. Baixe em: python.org/downloads
  2. Durante instalação, marque: "Add Python to PATH"
  3. Reinicie o terminal
  4. Verifique: python --version
Solução 3: Usar Node.js
  1. Baixe em: nodejs.org
  2. Instale e reinicie terminal
  3. Verifique: node --version
Solução 4: Abrir HTML diretamente

Navegue até frontend-web/static/index.html e abra no navegador.

⚠️ Limitações: Pode ter problemas com CORS em algumas funcionalidades.

❌ Erro CORS no Console do Navegador

Sintoma

Access to fetch at 'http://localhost:8080/api/...' from origin 'file://' 
has been blocked by CORS policy

Causa

Frontend aberto diretamente (file://) em vez de via servidor HTTP

Solução

Use um servidor HTTP:

.\iniciar-frontend.bat

# OU manualmente
cd frontend-web/static
python -m http.server 5500

🔐 Problemas de Autenticação

❌ Token JWT Inválido

Sintoma

  • Usuário é deslogado automaticamente
  • Erro 401 Unauthorized nas requisições
  • Console mostra: "Token inválido ou expirado"

Causas Possíveis

  • Token expirou (válido por 24h)
  • Backend foi reiniciado (secret do JWT mudou)
  • LocalStorage corrompido

Soluções

Solução 1: Fazer login novamente

Simplesmente faça login novamente. O sistema gerará novo token.

Solução 2: Limpar LocalStorage 
// No console do navegador (F12)
localStorage.clear();
location.reload();
Solução 3: Usar modo anônimo

Teste em janela anônima para garantir que não há cache/dados antigos.

❌ Senha Não Atende Requisitos

Requisitos de Senha

  • Mínimo 8 caracteres
  • Pelo menos 1 letra maiúscula
  • Pelo menos 1 número
  • Pelo menos 1 caractere especial (@$!%*?&)

Exemplos Válidos

  • Admin@123
  • Senha@123
  • Teste$2024

🔑 Configurar Recuperação de Senha por Email

Funcionalidade

Sistema permite que usuários recuperem senha via link enviado por email (Gmail SMTP).

📧 Passo 1: Configurar Gmail para Aplicativos

  1. Acesse: myaccount.google.com
  2. Vá em Segurança
  3. Ative Verificação em 2 etapas (obrigatório)
  4. Após ativar, volte em Segurança
  5. Procure por "Senhas de app"
  6. Crie uma senha de app com nome "SEJA SENAI"
  7. Copie a senha gerada (16 caracteres)

⚙️ Passo 2: Configurar application.properties

Edite: backend/src/main/resources/application.properties

# Email remetente (Gmail)
spring.mail.username=seu-email@gmail.com

# Senha de app gerada (não é a senha da conta!)
spring.mail.password=abcd efgh ijkl mnop

# Configurações SMTP do Gmail (já configuradas)
spring.mail.host=smtp.gmail.com
spring.mail.port=587
spring.mail.properties.mail.smtp.auth=true
spring.mail.properties.mail.smtp.starttls.enable=true

🔄 Passo 3: Reiniciar Backend

.\parar-sistema.bat
.\iniciar-backend.bat

✅ Passo 4: Testar Recuperação

  1. Acesse: forgot-password.html
  2. Digite um email cadastrado (ex: admin@senai.com)
  3. Verifique a caixa de entrada do email
  4. Clique no link de recuperação
  5. Defina nova senha

⚠️ Problemas Comuns

  • Erro 535: Senha de app incorreta ou 2FA não ativada
  • Email não chega: Verifique spam/lixo eletrônico
  • Timeout: Verifique conexão com internet e firewall
  • Token expirado: Link vale 30 minutos, solicite novo

🔒 Segurança

  • Tokens de recuperação expiram em 30 minutos
  • Cada token pode ser usado apenas uma vez
  • Email sempre mostra mensagem genérica (não revela se email existe)
  • Senhas devem atender requisitos: 8+ caracteres, maiúscula, minúscula, número, especial

📝 Problemas com Scripts

❌ Erro 400/403 ao Executar inserir-dados.bat

Sintomas

  • Erro 400: "Solicitação Incorreta" ao criar usuários
  • Erro 403: "Proibido" ao criar unidades/cursos/editais
  • Login do admin falhando

✅ Correção Aplicada (Março 2026)

Problema de "paradoxo do admin" foi resolvido:

  • Novo endpoint: POST /api/usuarios/setup-admin
  • Permite criar primeiro admin SEM autenticação
  • Só funciona se nenhum admin existir (bootstrap inicial)
  • Admin já é criado com ROLE_ADMIN
  • Script atualizado para usar endpoint correto

Solução

Se ainda estiver com problemas:

  1. Pare o backend: .\parar-sistema.bat
  2. Limpe o banco H2 (automático ao reiniciar)
  3. Inicie novamente: .\iniciar-tudo.bat

💡 Como funciona agora

1º Admin: Use /api/usuarios/setup-admin (público)

Próximos admins: Use /api/usuarios/admin (requer ROLE_ADMIN)

❌ Erro 404 ao Executar inserir-dados.bat

Sintoma

Invoke-RestMethod : {"timestamp":"2026-03-08T...","status":404,
"error":"Not Found"...

Causas Possíveis

  • Backend não está rodando
  • Backend ainda não terminou de inicializar
  • Porta 8080 não está acessível

Soluções

Solução 1: Verificar backend 
.\verificar-status.bat
Solução 2: Aguardar inicialização

Backend demora 30-60 segundos. Aguarde mensagem:

Started SejaSenaiApplication in X.XXX seconds
Solução 3: Reiniciar backend 
.\parar-sistema.bat
.\iniciar-backend.bat
# Aguarde inicializar
.\inserir-dados.bat

❌ Erro de Permissão no PowerShell

Sintoma

... não pode ser carregado porque a execução de scripts foi desabilitada 
neste sistema

Soluções

Solução 1: Executar com bypass (não requer admin) 
powershell -ExecutionPolicy Bypass -File popular-dados-teste.ps1
Solução 2: Alterar política (requer admin) 
# Abra PowerShell como Administrador
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
Solução 3: Usar .bat em vez de .ps1 
.\inserir-dados.bat

🗄️ Problemas com Banco de Dados

❌ H2 Console Não Abre

Verificações

1. Perfil H2 está ativo?

Verifique application.properties:

spring.profiles.active=h2
2. Backend está rodando? 
.\verificar-status.bat
3. URL correta?

http://localhost:8080/h2-console

4. Credenciais corretas?
  • JDBC URL: jdbc:h2:mem:testdb
  • Username: sa
  • Password: (deixe em branco)

✅ Correção Aplicada (Março 2026)

SecurityConfig foi atualizado para permitir H2 Console:

  • CSRF desabilitado para /h2-console/**
  • Frame options alterado de deny() para sameOrigin()
  • Endpoint público configurado

⚠️ Dados Sumiram no H2

Comportamento Esperado

H2 é um banco em memória. Dados são perdidos quando o backend para.

Soluções

Para manter dados entre reinícios:
  • Opção 1: Use MySQL (spring.profiles.active=mysql)
  • Opção 2: Execute inserir-dados.bat após cada reinício do backend

🗑️ Como Zerar o Banco de Dados

💡 Script Automatizado (Recomendado)

Use o script que detecta automaticamente o perfil ativo:

.\limpar-banco.bat

O script irá:

  • Detectar se está usando H2 ou MySQL
  • Executar o procedimento correto para cada banco
  • Opcionalmente reiniciar backend e popular dados

📘 Zerar Banco H2 (Banco em Memória)

Método 1: Automático (Recomendado)

O H2 é automaticamente zerado ao reiniciar o backend devido à configuração:

spring.jpa.hibernate.ddl-auto=create-drop

Passos:

  1. Pare o backend: .\parar-sistema.bat
  2. Inicie novamente: .\iniciar-backend.bat
  3. (Opcional) Popule dados: .\inserir-dados.bat
Método 2: Via Script 
.\limpar-banco.bat

Detecta H2 automaticamente e oferece reiniciar + popular em um único comando.

✅ Quando usar

  • Corrigir dados inconsistentes
  • Começar teste do zero
  • Resetar após mudanças nas entidades

📙 Zerar Banco MySQL (Banco Persistente)

⚠️ Atenção

MySQL usa spring.jpa.hibernate.ddl-auto=update - dados persistem entre reinícios!

Método 1: Script Automatizado 
.\limpar-banco.bat

Detecta MySQL e tenta executar comandos automaticamente (requer mysql CLI no PATH).

Método 2: MySQL Workbench (Manual)
  1. Abra MySQL Workbench
  2. Conecte ao servidor local
  3. Execute no SQL Editor:
DROP DATABASE IF EXISTS seja_senai_db;
CREATE DATABASE seja_senai_db;
  1. Reinicie o backend (tabelas serão recriadas)
  2. Execute .\inserir-dados.bat para popular
Método 3: MySQL Command Line 
mysql -u root -p
# Digite a senha quando solicitado

DROP DATABASE IF EXISTS seja_senai_db;
CREATE DATABASE seja_senai_db;
exit;

# Reinicie backend
.\parar-sistema.bat
.\iniciar-backend.bat

# Popule dados
.\inserir-dados.bat
Método 4: Deletar Apenas Tabelas (Alternativa) 
USE seja_senai_db;
SET FOREIGN_KEY_CHECKS = 0;

DROP TABLE IF EXISTS inscricao;
DROP TABLE IF EXISTS edital;
DROP TABLE IF EXISTS curso;
DROP TABLE IF EXISTS unidade;
DROP TABLE IF EXISTS password_reset_tokens;
DROP TABLE IF EXISTS usuario;

SET FOREIGN_KEY_CHECKS = 1;

🚨 Backup Antes de Zerar (Produção)

Se estiver usando MySQL em produção, SEMPRE faça backup antes:

mysqldump -u root -p seja_senai_db > backup_$(date +%Y%m%d).sql
