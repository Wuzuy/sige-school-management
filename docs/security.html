Visão Geral

O sistema SIGE implementa múltiplas camadas de segurança para proteger dados dos usuários e garantir a integridade do processo seletivo. Esta documentação detalha todas as medidas de segurança aplicadas.

⚠️ Importante: Esta documentação é destinada à equipe de desenvolvimento. Não compartilhe informações técnicas detalhadas com usuários finais.

🛡️ Segurança do Backend

1. Autenticação JWT (JSON Web Tokens)

Configuração

  • Secret Key: Chave de 256 bits configurável via application.properties
  • Algoritmo: HS256 (HMAC-SHA256)
  • Validade: 24 horas (86400000ms)
  • Renovação: Automática a cada requisição válida

Validações Implementadas

  • Verificação de assinatura do token
  • Validação de expiração
  • Verificação de formato (malformed)
  • Proteção contra tokens vazios ou inválidos
# application.properties
jwt.secret=SejaSenai2025SecretKeyForJWTTokenGenerationAndValidationMustBeLongEnoughForHS256
jwt.expiration=86400000

2. Senhas Fortes

Implementamos validação de senha forte para garantir segurança das contas de usuário:

Requisitos de Senha:

  • ✅ Mínimo de 8 caracteres
  • ✅ Pelo menos 1 letra maiúscula (A-Z)
  • ✅ Pelo menos 1 letra minúscula (a-z)
  • ✅ Pelo menos 1 número (0-9)
  • ✅ Pelo menos 1 caractere especial (@#$%^&+=!)
  • ✅ Sem espaços em branco

Classe: PasswordValidator.java

Validação: Frontend e Backend (dupla camada)

Criptografia: BCrypt com força 10 (padrão Spring Security)

3. Rate Limiting

Proteção contra ataques de negação de serviço (DoS) e força bruta:

Limites Globais

  • Bucket4j: 100 requisições por minuto por IP
  • Renovação: Intervalo de 1 minuto
  • Resposta: HTTP 429 (Too Many Requests)

Identificação de Cliente

  • IP do cliente (X-Forwarded-For)
  • Cache em memória (ConcurrentHashMap)
  • Limites por endpoint
// RateLimitFilter.java
Bandwidth limit = Bandwidth.classic(100, Refill.intervally(100, Duration.ofMinutes(1)));

4. Proteção contra Brute Force (Login)

Sistema de bloqueio temporário após tentativas falhadas de login:

Configuração:

  • Máximo de tentativas: 5 tentativas por usuário/IP
  • Tempo de bloqueio: 15 minutos
  • Chave de identificação: email + IP
  • Feedback: Número de tentativas restantes na resposta

Classe: LoginAttemptService.java

Resposta ao bloqueio: HTTP 429 com tempo restante em minutos

5. Headers de Segurança HTTP

Headers configurados no SecurityConfig.java para proteção adicional:

Header Valor/Configuração Proteção
Content-Security-Policy default-src 'self'; script-src 'self' 'unsafe-inline' XSS, Injection
X-XSS-Protection 1; mode=block XSS (Cross-Site Scripting)
X-Frame-Options DENY Clickjacking
Strict-Transport-Security max-age=31536000; includeSubDomains Man-in-the-Middle

6. CORS (Cross-Origin Resource Sharing)

Configurado para aceitar requisições de origens específicas:

@CrossOrigin(origins = "*") // Ambiente de desenvolvimento
// Em produção, especificar domínios permitidos:
// @CrossOrigin(origins = {"https://sige.com.br"})

7. Gestão de Exceções

GlobalExceptionHandler: Trata erros de forma segura sem expor detalhes internos

  • Captura DataIntegrityViolationException (dados duplicados)
  • Retorna mensagens genéricas (não expõe stack trace)
  • Log de erros para análise interna

🔐 Segurança do Frontend

1. Sanitização de Inputs

Todas as entradas de usuário são sanitizadas antes do processamento:

// scripts.js
function sanitizeHTML(str) {
  if (!str) return '';
  const temp = document.createElement('div');
  temp.textContent = String(str);
  return temp.innerHTML;
}

function sanitizeInput(value) {
  if (!value) return '';
  return String(value).trim().slice(0, 500); // Limita tamanho
}

2. Validações Client-Side

Email

Regex: /^[^\s@]+@[^\s@]+\.[^\s@]+$/

CPF

Formato: 11 dígitos numéricos

Senha Forte

Mesmos requisitos do backend

3. Gestão Segura de Tokens

  • Armazenamento: localStorage com validação
  • Validação JWT: Estrutura de 3 partes separadas por pontos
  • Limpeza automática: Tokens inválidos são removidos
  • Verificação: A cada carregamento de página
function isValidToken(token) {
  if (!token || typeof token !== 'string') return false;
  const parts = token.split('.');
  return parts.length === 3;
}

4. Proteção XSS

  • Sanitização de HTML em todos os textos exibidos
  • Uso de textContent ao invés de innerHTML
  • Escape de caracteres especiais
  • Content Security Policy configurado

📋 Checklist de Segurança

Backend ✅

  • ✅ Autenticação JWT com secret configurável
  • ✅ Validação de tokens (assinatura, expiração, formato)
  • ✅ Senhas criptografadas com BCrypt
  • ✅ Validação de senha forte (8+ chars, maiúscula, minúscula, número, especial)
  • ✅ Rate Limiting global (100 req/min por IP)
  • ✅ Proteção contra Brute Force (5 tentativas, 15min bloqueio)
  • ✅ Headers de segurança HTTP (CSP, XSS, Frame, HSTS)
  • ✅ CORS configurado
  • ✅ Gestão segura de exceções
  • ✅ Roles e autorização baseada em permissões

Frontend ✅

  • ✅ Sanitização de inputs (HTML e texto)
  • ✅ Validação de email, CPF e senha forte
  • ✅ Validação de tokens JWT
  • ✅ Proteção XSS (textContent, escape)
  • ✅ Limpeza automática de tokens inválidos
  • ✅ Limitação de tamanho de inputs (500 chars)
  • ✅ Feedback de segurança ao usuário

🔧 Manutenção e Boas Práticas

Senhas e Secrets

  • NUNCA commitar secrets no código
  • Usar variáveis de ambiente em produção
  • Rotacionar JWT secret periodicamente (a cada 90 dias)
  • Manter BCrypt strength >= 10

Logs e Monitoramento

  • Monitorar tentativas de login falhadas
  • Alertar sobre rate limiting excessivo
  • Auditar mudanças de permissões de usuário
  • Log de acessos administrativos

Atualizações

  • Manter dependências atualizadas (mvn versions:display-dependency-updates)
  • Atualizar Spring Security regularmente
  • Revisar CVEs de bibliotecas usadas
  • Testar segurança após cada atualização
