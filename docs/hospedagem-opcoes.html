2️⃣ Railway.app - Backend + Database

🚆 Por que Railway?

  • ✅ Deploy automático via GitHub
  • ✅ MySQL/PostgreSQL incluído (grátis)
  • ✅ Suporta Spring Boot nativamente
  • ✅ Variáveis de ambiente fáceis
  • ✅ Logs em tempo real
  • ✅ Domínio gratuito (.railway.app)

2.1. Configuração Passo a Passo

Passo 1: Criar conta no Railway

  1. Acesse: https://railway.app
  2. Clique em "Start a New Project"
  3. Faça login com GitHub (autenticação OAuth)
  4. ✅ Você ganha $5 de crédito grátis/mês (sem cartão necessário)

Passo 2: Configurar Projeto

  1. No dashboard, clique "+ New Project"
  2. Selecione "Deploy from GitHub repo"
  3. Escolha o repositório: sige
  4. Railway detecta automaticamente que é Spring Boot
  5. Clique em "Deploy Now"

Passo 3: Adicionar MySQL Database

  1. No projeto, clique "+ New" → "Database" → "MySQL"
  2. Railway cria banco automaticamente
  3. Copie as credenciais que aparecem na aba "Connect": 
    MYSQL_HOST=containers-us-west-xxx.railway.app
MYSQL_PORT=6389
MYSQL_DATABASE=railway
MYSQL_USER=root
MYSQL_PASSWORD=gxxxxxxxxxxxxxxx

Passo 4: Configurar Variáveis de Ambiente

  1. No serviço do backend, vá em "Variables"
  2. Adicione as seguintes variáveis: 
    SPRING_DATASOURCE_URL=jdbc:mysql://${MYSQL_HOST}:${MYSQL_PORT}/${MYSQL_DATABASE}
SPRING_DATASOURCE_USERNAME=${MYSQL_USER}
SPRING_DATASOURCE_PASSWORD=${MYSQL_PASSWORD}
SPRING_JPA_HIBERNATE_DDL_AUTO=update
JWT_SECRET=seu_super_secret_key_aqui_com_32_caracteres_minimo
CORS_ALLOWED_ORIGINS=https://seu-frontend.vercel.app
  3. Clique em "Add" para salvar

Passo 5: Deploy e Obter URL

  1. Railway faz deploy automaticamente (aguarde ~3 minutos)
  2. Na aba "Settings" → "Networking", clique "Generate Domain"
  3. ✅ Sua API estará disponível em: https://sige-production.up.railway.app
  4. Teste: https://sige-production.up.railway.app/api/cursos

⚠️ Limitações do Plano Grátis

  • $5 crédito/mês = ~500 horas de execução
  • 512MB RAM (suficiente para Spring Boot básico)
  • O serviço pode "dormir" após inatividade (demora ~30s para acordar)
  • Uptime: ~70% (suficiente para apresentação)

2.2. Atualizar application.properties

No arquivo backend/src/main/resources/application.properties, adicione:

spring.datasource.url=${SPRING_DATASOURCE_URL:jdbc:mysql://localhost:3306/sige}
spring.datasource.username=${SPRING_DATASOURCE_USERNAME:root}
spring.datasource.password=${SPRING_DATASOURCE_PASSWORD:root}
spring.jpa.hibernate.ddl-auto=${SPRING_JPA_HIBERNATE_DDL_AUTO:update}

jwt.secret=${JWT_SECRET:default_secret_only_for_local_dev}
cors.allowed.origins=${CORS_ALLOWED_ORIGINS:http://localhost:8080}

server.port=${PORT:8080}

✅ O ${PORT:8080} é importante! Railway injeta automaticamente a variável PORT.

3️⃣ Vercel - Frontend Web

⚡ Por que Vercel?

  • ✅ Deploy automático via Git (push = deploy)
  • ✅ CDN global (site rápido no mundo todo)
  • ✅ HTTPS automático
  • ✅ Preview de branches (testa antes de publicar)
  • ✅ 100% grátis para frontend estático

3.1. Configuração Passo a Passo

Passo 1: Criar conta no Vercel

  1. Acesse: https://vercel.com
  2. Clique em "Sign Up"
  3. Faça login com GitHub

Passo 2: Importar Projeto

  1. No dashboard, clique "Add New..." → "Project"
  2. Selecione o repositório sige
  3. Configure:
    • Framework Preset: Other
    • Root Directory: frontend-web/static
    • Build Command: (deixe vazio - é site estático)
    • Output Directory: .
  4. Clique em "Deploy"

Passo 3: Atualizar URL da API no Frontend

No arquivo frontend-web/static/scripts.js, atualize a URL da API:

// No início do arquivo
const API_BASE_URL = 'https://sige-production.up.railway.app/api';

// Exemplo de fetch:
fetch(`${API_BASE_URL}/cursos`)
  .then(response => response.json())
  .then(data => console.log(data));

Passo 4: Deploy Completo

  1. Commit e push das mudanças para GitHub
  2. ✅ Vercel faz deploy automático (1-2 minutos)
  3. Acesse seu site em: https://sige.vercel.app

✅ Seu frontend está no ar!

Domínio: https://sige.vercel.app
Deploy automático: toda vez que você der git push na branch main

4️⃣ GitHub Pages - Documentação

📚 Por que GitHub Pages?

  • ✅ 100% gratuito para sempre
  • ✅ Integração nativa com GitHub
  • ✅ HTTPS automático
  • ✅ Perfeito para documentação estática
  • ✅ Domínio: username.github.io/repository

4.1. Configuração Passo a Passo

Passo 1: Ativar GitHub Pages

  1. No GitHub, vá no repositório sige
  2. Clique em "Settings"
  3. Na barra lateral, clique em "Pages"
  4. Em "Source", selecione:
    • Branch: main
    • Folder: /docs
  5. Clique em "Save"

Passo 2: Aguardar Deploy

  1. GitHub processa automaticamente (1-2 minutos)
  2. ✅ Documentação estará disponível em:
    https://lucas.github.io/sige/
  3. Teste acessando: https://lucas.github.io/sige/index.html

Passo 3: Configurar Links Relativos

Se houver problemas com CSS/JS, atualize os caminhos nos arquivos HTML da pasta docs/:

<!-- De: -->
<link rel="stylesheet" href="site.css" />

<!-- Para: -->
<link rel="stylesheet" href="/sige/site.css" />

⚠️ Atenção aos caminhos

GitHub Pages adiciona o nome do repositório na URL. Use caminhos absolutos começando com /sige/

4.2. Deploy Automático com GitHub Actions (Opcional)

Crie o arquivo .github/workflows/deploy-docs.yml:

name: Deploy Docs

on:
  push:
    branches: [main]
    paths:
      - 'docs/**'

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Deploy to GitHub Pages
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./docs

🔧 Troubleshooting

Problema: Backend não conecta no banco

Solução:

  1. Verifique se as variáveis de ambiente estão corretas no Railway
  2. Confirme que SPRING_DATASOURCE_URL usa jdbc:mysql://
  3. Verifique os logs no Railway: aba "Deployments" → clique no último deploy

Problema: CORS bloqueado no frontend

Solução:

  1. No Railway, adicione a variável: CORS_ALLOWED_ORIGINS=https://sige.vercel.app
  2. No backend, verifique SecurityConfig.java se está lendo a variável corretamente
  3. Reinicie o backend após mudanças

Problema: CSS quebrado no GitHub Pages

Solução:

  1. Altere os caminhos nos HTML de href="site.css" para href="/sige/site.css"
  2. Ou use caminhos relativos: href="./site.css"
  3. GitHub Pages adiciona o nome do repositório na URL base

Problema: Backend "dormindo" (cold start)

É normal no plano grátis! Após 15min de inatividade, o serviço entra em sleep.

Como resolver:

  • Aceite o delay de ~30s no primeiro acesso
  • Ou configure um ping a cada 10 minutos (UptimeRobot grátis)
  • Ou migre para Railway Pro ($20/mês sem sleep)
